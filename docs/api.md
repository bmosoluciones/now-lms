# NOW LMS Public API Documentation

This documentation describes the public API of NOW LMS, designed primarily for integration with external services like Admiral Harbor.

## 1. Introduction

The Public API allows external systems to:
- Validate connectivity and authentication.
- Consult public course information using a unique code.
- Execute remote user enrollment after a confirmed payment or plan assignment.

The integration maintains a clear separation of responsibilities:
- **External System**: Manages the commercial catalog, discounts, billing, and purchase experience.
- **NOW LMS**: Manages users, courses, progress, evaluations, certificates, validation, and recertification.

---

## 2. Authentication

The API uses **API Keys** for authentication. These keys must be generated by a NOW LMS administrator in the settings panel.

### Required Header
You must provide the API Key in one of the following headers:

1. **Standard Bearer Token:**
   ```
   Authorization: Bearer <your_api_key>
   ```

2. **Custom API Key Header:**
   ```
   X-API-Key: <your_api_key>
   ```

**Security Note:** API Keys are stored as SHA-256 hashes in the database. They should be treated as sensitive credentials and never shared or exposed in client-side code.

---

## 3. Rate Limiting

A basic rate limit is applied per API Key to prevent abuse:
- **Limit:** 60 requests per minute.
- **Window:** 60 seconds.

If the limit is exceeded, the API will return a `429 Too Many Requests` status code.

## 4. Endpoints

### 4.1. Health / Handshake
`GET /api/v1/public/ping`

Validates that the LMS is available and the API Key is valid.

**Response (Success - 200 OK):**
```json
{
  "status": "ok",
  "service": "NOW LMS",
  "version": "1.2.5"
}
```

---

### 4.2. Consult Course by Code
`GET /api/v1/public/courses/{course_code}`

Retrieves public information about a course using its unique code.

**Response (Success - 200 OK):**
```json
{
  "code": "VERSER_BASIC",
  "title": "Verser Basic",
  "description": "Curso básico de introducción a Verser.",
  "duration_hours": 8,
  "course_type": "certification",
  "thumbnail_url": "https://lms.example.com/static/uploads/images/VERSER_BASIC/portada.jpg",
  "is_active": true,
  "certificate_available": true,
  "recertification_required": true,
  "recertification_period_years": 3,
  "resources": ["video", "quiz", "certificate"]
}
```

**Response (Not Found - 404 Not Found):**
```json
{
  "error": "course_not_found",
  "message": "Course code was not found."
}
```

---

### 4.3. Remote Enrollment
`POST /api/v1/public/enrollments`

Enrolls a user in a specific course. This endpoint is **idempotent** using the `request_id`.

**Payload:**
```json
{
  "request_id": "uuid-generated-by-external-system",
  "course_code": "VERSER_BASIC",
  "email": "user@example.com",
  "payment_confirmed": true
}
```

**Payload Rules:**
- `request_id`: Required (string). Used to prevent duplicate processing.
- `course_code`: Required (string). Unique code of the course.
- `email`: Required (string). Valid email address of the student.
- `payment_confirmed`: Required (boolean). Must be `true` to proceed.

#### User Creation Logic:
1. **Existing User:** If the email exists in NOW LMS, the user is enrolled in the course, and a notification email is sent.
2. **New User:** If the email does not exist, a new user is created with `pending_verification` status. The user is enrolled, and an invitation email is sent with a link to verify the account and set a password.

**Response (User Created - 201 Created):**
```json
{
  "status": "enrolled",
  "user_status": "pending_verification",
  "course_code": "VERSER_BASIC",
  "email": "user@example.com",
  "message": "User was created as pending verification and enrolled successfully."
}
```

**Response (Existing User - 201 Created):**
```json
{
  "status": "enrolled",
  "user_status": "existing_user",
  "course_code": "VERSER_BASIC",
  "email": "user@example.com",
  "message": "Existing user was enrolled successfully."
}
```

**Response (Already Processed - 200 OK):**
*Returned if the `request_id` was already handled.*
```json
{
  "status": "already_processed",
  "course_code": "VERSER_BASIC",
  "email": "user@example.com"
}
```

**Response (Already Enrolled - 200 OK):**
```json
{
  "status": "already_enrolled",
  "course_code": "VERSER_BASIC",
  "email": "user@example.com"
}
```

### 4.4. List Unread Contact Messages
`GET /api/v1/public/contact-messages`

Retrieves a list of all contact form messages that are in `not_seen` (unread) status. This can be consumed by external systems like a CRM.

**Response (Success - 200 OK):**
```json
[
  {
    "id": "01J41Y6XN...",
    "name": "John Doe",
    "email": "john@example.com",
    "subject": "Inquiry about partnership",
    "message": "Hello, we are interested in...",
    "status": "not_seen",
    "created_at": "2026-07-31T23:22:01.180000"
  }
]
```

---

### 4.5. Mark Contact Message as Read
`POST /api/v1/public/contact-messages/{message_id}/read`

Marks a specific contact message as read by updating its status to `seen`.

**Response (Success - 200 OK):**
```json
{
  "status": "success",
  "message_id": "01J41Y6XN...",
  "new_status": "seen",
  "message": "Message marked as read successfully."
}
```

**Response (Not Found - 404 Not Found):**
```json
{
  "error": "message_not_found",
  "message": "Contact message ID was not found."
}
```

## 5. Certification and Recertification

Courses can be configured to require recertification.

### Recertification Fields:
- `recertification_required`: Boolean.
- `recertification_period_years`: Integer (nullable).

### Certificate Validity:
When a certificate is issued:
- If recertification is required, an `expires_at` date is calculated (Issue Date + Period).
- If not required, `expires_at` remains null (permanent certificate).

The public QR validation page will display the status as **"Vigente"** (Valid) or **"No Vigente"** (Expired) based on the current date relative to `expires_at`.

---

## 6. Audit and Traceability

All remote enrollment requests are logged in the `remote_enrollment_requests` table, storing:
- Request ID
- Course Code
- User Email
- Status (processed/failed)
- API Key used
- Processed timestamp
- Raw JSON payload for debugging
